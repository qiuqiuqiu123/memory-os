# 项目经验

- 调试部署与生产容量要求分开：用户首期只有 8GB/12GB 内存，采用核心默认启动、Langfuse profile 按需启动，不能把完整栈资源估算当作启动核心的硬门槛。
- 事件同步按提交可见顺序设计，不把序列分配顺序当作提交顺序。客户端写入确认与拉取游标必须分离。
- 外部模型返回空事实与调用失败必须区分；调用真实 SDK 不等于 SDK 不会吞错，需检查其失败语义。
- 快照去重必须允许 A→B→A；派生事件使用持久修订号，幂等状态与事件事务提交。
- 验证分别记录数据库/向量存储、离线提供方fixture、真实模型和完整Compose，不把一类通过当成另一类通过。
- OpenAI兼容服务的Base URL与完整接口URL必须区分：SDK会自行追加/embeddings或/chat/completions。出现curl成功而平台404时，先核对最终请求路径，再检查可选参数；用真实响应长度确认维度，不照搬接口文档里的占位值。
- 向用户提供公网MCP接入步骤前，必须从客户端网络用实际Host完成initialize和tools/list；REST健康检查或localhost MCP成功不足以证明公网MCP可用。MCP默认Host白名单需要单独核对。
- 用户期望记忆系统默认采集大部分执行轨迹，由后台分析产出结论和优化点；不能把需求缩减为用户明确要求时才保存的手工记事。明确保存与自动轨迹采集必须作为并行入口，原始轨迹与提炼记忆分层存储。
- 用户要求通过提示词/Hook等插件接入现有Codex，不希望安装额外常驻日志扫描器。实现前必须明确接入形态；不能将独立JSONL采集进程称作Hook/插件，也不能在跨机器扩展时继续沿用被纠正的形态。此前并未构建或修改Codex本体；解释事实并停用旧采集，再按MCP+提示词重做，不删除正常Codex应用。
- 客户端接入配置优先使用约定的 URL/key 环境变量；不要要求用户额外创建密钥文件。环境变量模式只持久化变量名，Hook 与 MCP 从运行环境读取密钥；说明桌面进程继承环境的边界。公网 HTTP 调试必须由显式开关启用，默认仍拒绝，安装器和运行时需采用相同校验。
